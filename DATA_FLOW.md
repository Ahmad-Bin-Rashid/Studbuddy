# StudBuddy — Data Flow

---

## 1. Data Flow Principles

1. **AppDataStore is the single source of truth.** No Activity maintains its own persistent copy.
2. **All reads happen in `onResume()`** — not `onCreate()`. This ensures data is fresh after returning from dialogs or background.
3. **All writes go through `AppDataStore`** — never directly to `SharedPreferences`.
4. **`SharedPrefManager.sync()` is called by `AppDataStore` automatically** after every mutation. Activities do not call it.
5. **All IDs are UUIDs** generated by `UUID.randomUUID().toString()`.

---

## 2. Full Read Lifecycle

```
Activity.onResume()
    │
    ▼
AppDataStore.get<Module>List(): List<Model>
    │
    ├─ Is in-memory cache populated?
    │   ├─ YES → return cached list immediately
    │   └─ NO  → SharedPrefManager.getString(KEY_<MODULE>)
    │               │
    │               ├─ Returns JSON string
    │               │     → JSON → List<Model> deserialization
    │               │     → populate in-memory cache
    │               │     → return list
    │               │
    │               └─ Returns null (first run)
    │                     → return emptyList()
    │
    ▼
Activity receives List<Model>
    │
    ▼
adapter.updateList(list)
    │
    ▼
RecyclerView renders items
    │
    ▼
updateEmptyState() — show/hide empty view
```

## 3. Full Write Lifecycle (Add)

```
User fills dialog → taps Save
    │
    ▼
Activity.validateInput() → returns Boolean
    ├─ false → Toast error, keep dialog open
    └─ true  →
            │
            ▼
        Build Model object:
        val entry = TimetableEntry(
            id = UUID.randomUUID().toString(),
            courseName = courseName,
            ...
        )
            │
            ▼
        AppDataStore.addTimetableEntry(entry)
            │
            ├─ inMemoryList.add(entry)
            ├─ serialize inMemoryList to JSON
            └─ SharedPrefManager.putString(KEY_TIMETABLE, json)
            │
            ▼
        adapter.addItem(entry)   — or adapter.updateList(AppDataStore.getTimetableList())
            │
            ▼
        updateEmptyState()
            │
            ▼
        Dialog dismissed
```

## 4. Full Write Lifecycle (Edit)

```
User taps Edit on item → dialog pre-filled with existing data
    │
    ▼
User modifies fields → taps Save
    │
    ▼
Activity.validateInput() → returns Boolean
    ├─ false → Toast error, keep dialog open
    └─ true  →
            │
            ▼
        Build updated Model:
        val updated = existing.copy(
            courseName = newName,
            ...
        )
            │
            ▼
        AppDataStore.updateTimetableEntry(updated)
            │
            ├─ val idx = inMemoryList.indexOfFirst { it.id == updated.id }
            ├─ inMemoryList[idx] = updated
            ├─ serialize to JSON
            └─ SharedPrefManager.putString(KEY_TIMETABLE, json)
            │
            ▼
        val pos = timetableList.indexOfFirst { it.id == updated.id }
        timetableList[pos] = updated
        adapter.notifyItemChanged(pos)
```

---

## 5. Full Write Lifecycle (Delete)

```
User taps Delete → confirmation dialog shown
    │
    ▼
User confirms
    │
    ▼
AppDataStore.deleteTimetableEntry(entryId: String)
    │
    ├─ inMemoryList.removeAll { it.id == entryId }
    ├─ serialize to JSON
    └─ SharedPrefManager.putString(KEY_TIMETABLE, json)
    │
    ▼
val pos = timetableList.indexOfFirst { it.id == entryId }
timetableList.removeAt(pos)
adapter.notifyItemRemoved(pos)
    │
    ▼
updateEmptyState()
```

## 6. SharedPreferences Key Registry

**Defined in `SharedPrefManager.kt` — DO NOT add keys elsewhere.**

```kotlin
object Keys {
    const val KEY_TIMETABLE    = "studbuddy_timetable"
    const val KEY_ASSIGNMENTS  = "studbuddy_assignments"
```

## 7. JSON Serialization Contract

Each model must implement `toJson()` and a companion `fromJson(JSONObject)`.

### Example: Assignment

```kotlin
data class Assignment(
    val id: String,
    val title: String,
    val courseName: String,
    val dueDate: Long,           // epoch milliseconds
    val priority: Priority,
    val isCompleted: Boolean
) {
    fun toJson(): JSONObject = JSONObject().apply {
        put("id", id)
        put("title", title)
        put("courseName", courseName)
        put("dueDate", dueDate)
        put("priority", priority.name)
        put("isCompleted", isCompleted)
    }

    companion object {
        fun fromJson(obj: JSONObject): Assignment = Assignment(
            id = obj.getString("id"),
            title = obj.getString("title"),
            courseName = obj.getString("courseName"),
            dueDate = obj.getLong("dueDate"),
            priority = Priority.valueOf(obj.getString("priority")),
            isCompleted = obj.getBoolean("isCompleted")
        )
    }
}
```

### List Serialization (in AppDataStore)

```kotlin
// Serialize
private fun serializeAssignments(list: List<Assignment>): String {
    val array = JSONArray()
    list.forEach { array.put(it.toJson()) }
    return array.toString()
}

// Deserialize
private fun deserializeAssignments(json: String): MutableList<Assignment> {
    return try {
        val array = JSONArray(json)
        (0 until array.length()).map { Assignment.fromJson(array.getJSONObject(it)) }.toMutableList()
    } catch (e: Exception) {
        mutableListOf()
    }
}
```

## 8. In-Memory Cache Invalidation

The in-memory cache is **never manually invalidated**. It is only rebuilt when:
- The app process is killed (cache is lost — reloaded from SharedPrefs on next `onResume`)
- `AppDataStore.clearAll()` is called (resets both cache and SharedPrefs)

```kotlin
// AppDataStore — cache fields
private var timetableCache: MutableList<TimetableEntry>? = null
private var assignmentsCache: MutableList<Assignment>? = null
private var attendanceCache: MutableList<AttendanceRecord>? = null
private var examsCache: MutableList<Exam>? = null
private var coursesCache: MutableList<Course>? = null

fun getTimetableList(): List<TimetableEntry> {
    if (timetableCache == null) {
        val json = SharedPrefManager.getString(Keys.KEY_TIMETABLE) ?: return emptyList()
        timetableCache = deserializeTimetable(json)
    }
    return timetableCache!!.toList() // Return copy — caller cannot modify cache directly
}
```

## 9. Data Initialization

`AppDataStore.initialize(context)` is called **once** in `MainActivity.onCreate()`:

```kotlin
// MainActivity.kt
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    AppDataStore.initialize(applicationContext)
    setContentView(R.layout.activity_main)
    setupNavigationButtons()
}
```

```kotlin
// AppDataStore.kt
object AppDataStore {
    private lateinit var sharedPrefManager: SharedPrefManager

    fun initialize(context: Context) {
        sharedPrefManager = SharedPrefManager(context)
        // Warm up caches (optional — lazy loading is also acceptable)
    }
}
```

## 10. Cross-Module Data Sharing

Some modules share data. This is the ONLY allowed cross-module data flow:

| Source Module | Data Shared | Consumer Module | Mechanism |
|---|---|---|---|
| GPA (courses) | `Course.name` list | Assignments (course picker) | `AppDataStore.getCourseNames(): List<String>` |
| GPA (courses) | `Course.name` list | Attendance (course picker) | `AppDataStore.getCourseNames(): List<String>` |
| GPA (courses) | `Course.name` list | Timetable (course picker) | `AppDataStore.getCourseNames(): List<String>` |
| GPA (courses) | `Course.name` list | Exams (course picker) | `AppDataStore.getCourseNames(): List<String>` |

**Rule:** Consumer modules call `AppDataStore.getCourseNames()` to populate Spinners. They never import or reference the `Course` model or `GpaActivity` directly.
